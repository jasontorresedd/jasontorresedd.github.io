Multimedia Production

Dashboard

This is an introduction to a dashboard developed with 4 years of data from leading multimedia production for more than 100 online courses at The George Washington University (GWU). (To learn a bit about that work, please see my page on learning and media operations.) Rather than the data sit forever silent, the dashboard tells a data story of a large operational and cultural transformation to increase team collaboration, streamline production workflows, reduce costs, open time for broader work, and achieve time for team members to take leave and/or pursue professional development.

Story

During the five years I was the Director of Strategic Digital Learning Initiatives at GWU, a big part of my job was overseeing a team of Multimedia Producers and influencing a team of Instructional Designers in the design and development of online courses from the central library. During my first year, we were all working from home during the COVID-19 pandemic. But upon finally going to campus in August 2021, I put in place a new data capture strategy for tracking performance, along with starting a workflow transformation. By the time I left GWU in summer 2025, I had led a significant reduction in time to deliver online courses and overall cost to produce them. Built from data collected from that time, this dashboard tells the story and provides the evidence for my effectiveness as an operations leader.

Why it was built

Reason 1: To provide the evidence of an operational transformation that I helmed but that was delivered by teams of Multimedia Producers and Instructional Designers. The impact was real, with both time to deliver projects and costs being cut in half from the time I started to the time I left GWU.

Reason 2: To demonstrate what I can achieve with Claude Code when taking a real dataset and turning it into a visual story. My process involves a lot more than uploading a spreadsheet, writing a few prompts, and then hoping the results are close to good.

The data source

The data was collected by me from August 2021 to June 2025 primarily using dashboards I designed in Monday.com. Team members would input values for different parts of their project and media production progress. Some they would also self-report during weekly check-ins. I captured the data in a single Microsoft Excel spreadsheet with each production term in a single tab. All input was manual over the years.

Since my departure from GWU in June 2025, the data has sat dormant.

Development

There were four phases to developing the dashboard. See below to learn about each phase. While some of these relied solely on my effort, others were done for or in partnership with Claude.

01

Data preparation

The existing spreadsheet was formatted with colors, separated rows, formulas, and comments that would be problematic for Claude to read. If shared in its original format, it would likely cause more work to fix any output. Over a few hours, I filled gaps where I knew the correct data, input formulas to ensure cells were populated, and then went about removing any formatting to ensure a complete set of rows and columns. With a clean dataset that could be exported to a CSV file, I moved to the next step.

02

Designing the style board

For styling, I first thought about colors. I went into one of my libraries for inspiration, then worked with a color picker to select 6 colors for data and 1 color for the background. Afterwards, I thought about fonts, but decided to keep with the primary fonts for my website. Next, I used the Design feature in Claude to create a style board to guide how these and other design elements would work together to tell a data story. When done, I exported the style guide as Markdown to share with the instructions I would write for Claude.

03

Instructions development

At this point I sat down and wrote out a full set of background, context, and instructions for Claude guiding how I wanted it to understand what I was providing and what I wanted to build. My instructions included six sections: 1) overview, 2) audience, 3) data sources, 4) presentation, 5) target output, and 6) technical specifications. Within this I provided details on how to interpret each column in the spreadsheet, data cards and functions I wanted in the dashboard, and background notes about time periods and workflows it would see in the data. These instructions were saved as Markdown.

04

Development procedure

This phase was only begun once data preparation, the style board, and the instructions were settled. Of those, I iterated with Claude on the style board a bit more after it was drafted, and I walked away and returned to the instructions a few times as I did other work. But once those were done, I did the following:

  • Step 1: Created a project folder on my desktop and included the instructions and style guide in Markdown, a folder with fonts, and the full dataset in a CSV file. I also included blank HTML and JS files following the file names I outlined in the instructions, and a CSS file following the same file naming in the instructions, but including the basic layers I wanted the CSS built within.
  • Step 2: Opened the folder in VS Code and launched the Claude Code plug-in.
  • Step 3: Instructed Claude to read my instructions and the style guide in the project folder, then execute on those. I used Opus 5.5 and set effort to 'High'.
  • Step 4: After about 10 minutes, Claude had drafted the HTML, CSS, and JS files I had asked for. I reviewed these before going forward to gain orientation and see how it drafted the dashboard against my instructions and style guide.
  • Step 5: From here I went through a couple of hours iterating with Claude on all aspects of the dashboard. This included redesigning cards, adding cards, and dropping cards. While doing this, I would manually revise language in the HTML and JS files. Before finalizing I asked it to make a pass to identify any typos or coding errors that needed fixing.
  • Step 6: I conversed with Claude on how this would be released on GitHub Pages and ensured that the CSV file would not be needed. I made adjustments to the HTML header to keep it in alignment with other website pages.
  • Step 7: In the last step of development Claude produced a revised version of the style guide incorporating all design changes we made. I then archived the work and moved relevant project files into my GitHub repository.

Functions

The following are a few functions that you can operate within the dashboard.

Persistent chapter navigation
A top bar jumps between Overview, Production, Media, Phases, Time, People, Costs, and Appendix.
Deep use of filters
Narrow every chart by Year, College, Media, and Cost.
Tooltips galore
Hover a mark for exact values. Estimated costs are marked “est.”
Small screen notice
Built for tablets and larger. Phones see a notice first, with an option to view anyway.
